title: "Troubleshooting"
description: "Fix the most common recording, transcription, summary, and calendar problems."
---

## Audio is missing

Open **Settings → Permissions** and confirm:

```bash
cargo install --locked --path apps/cli
meetspace --version
```

If a permission is denied, use **Open** to change it in macOS Settings, then restart Meetspace.

## The transcript is not live

Open **Settings → Transcription** and check the selected model. **Live** models transcribe during the meeting. **After recording** models wait until you stop.

```bash
meetspace --json doctor
```

Open the Meetspace desktop app once if the database does not exist, then retry:

```bash
meetspace --json meetings list --limit 5
```

For LM Studio and Ollama, confirm the local server is running. See [Transcription and AI](/ai-setup).

```bash
meetspace --db-path /path/to/app.db --json meetings list
```

Open **Calendar** and confirm the account is connected and the calendar is enabled. Refresh the calendar list. Reconnect any account marked **Reconnect required**.

For Apple Calendar, also check **Settings → Permissions → Calendar**.

Remove the search filter and list recent meetings. Confirm you opened the same Meetspace data directory as the desktop app.

Open **Settings → App → Storage** and check **Audio file retention**. Meetspace can delete audio immediately or after a selected period while keeping the note and transcript.

See [Data, privacy, and retention](/data-and-privacy#choose-how-long-audio-is-kept) for every retention option.

## An imported file does nothing

Audio imports accept WAV, MP3, OGG, MP4, M4A, FLAC, WebM, and AAC. Transcript imports accept SRT and VTT.

```bash
meetspace --json meetings list --limit 1
```

Then confirm the client launches `meetspace` with `mcp` as an argument. Use an absolute command path if the client's environment does not inherit your shell `PATH`.
